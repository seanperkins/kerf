# Deep review, 2026-10-20

A read-through of every module at `f565916` (branch `feat/export-deepest-cut`), done on the
`review/deep-review` branch in the `.worktrees/review` worktree. Six reviewers each read one area in
full (CADCore+CGeom, CAMCore, PostCore+export, app model, app UI, the test suite); the lead verified
each finding against the code before fixing it. Every fix has a regression test
(`Tests/*/ReviewRegressionTests.swift`, `HostileInputTests.swift`, `PostRobustnessTests.swift`,
`CGeomHostileInputTests.swift`). Build and the full suite are green: 1051 tests.

## Fixed on this branch

### Build and tests
- `scripts/build.sh` and `scripts/swiftpm-env.sh`: SwiftPM's own `sandbox-exec` cannot nest inside an
  agent shell's sandbox; the scripts probe for that and add `--disable-sandbox` only then. `test.sh`,
  `bundle.sh` and `ui.sh` use it. AGENTS.md and README now say to build through the scripts.
- The Finder-icon test skips (with a reason) when the process is sandboxed instead of failing.
- Two compiler warnings cleared.

### Safety (G-code)
- **Last pass + automatic tabs** (`ProfileOperation`): the finishing lap laid its tabs out from
  wherever it started, so with two or more parts the lap cut the roughing tabs away and the parts
  came loose. The finishing lap now reuses the roughing tab centres.
- **Single-toolpath export used the shown sheet's job** (`outputProject(for:)`): a toolpath on a
  thicker sheet was posted, validated and sent home with the thinner sheet's Z numbers. In
  spoilboard mode the footer rapid went through the stock. It now uses the sheet the toolpath was
  calculated for.
- **Save Tiled G-code** exported every sheet and both sides into one tile set; it now exports what
  every other route exports (the shown side of the current sheet).
- **Failed operations were silently left out** of Save All and Save Tiled (Export only warned); an
  enabled operation with no toolpaths is now an error, so "Save Anyway" has to be confirmed.
- **Sub-resolution arcs**: an arc whose ends round to the same point was written as G2/G3 with
  I/J, which a controller runs as a full circle at depth. The writer now emits a line for any arc
  shorter than two output digits.
- **NaN/inf coordinates** reached the file as `Xnan` with only a warning; the post now refuses them
  (`PostError.nonFiniteMove`).
- **Control characters in names** (a tool CSV can carry a newline) could start a new uncommented
  G-code block; they are now spaces.
- **Toolpath bounds ignored arc bulges**, so grouping by tool could reorder a carve ahead of the
  circle pocket that contains it; bounds now include the quadrant points of arcs.
- **Tiles kept the whole job's datum offset and home**, shifting every tile and sending the footer
  off the tile; each tile job now has no datum offset and parks at its own corner.
- **Merge With Next** re-enabled a toolpath that was turned off on purpose (the inlay plug); it now
  refuses when the flags differ.
- **Nested and plated copies of a profile with manual tabs** got no tabs; copies inherit the
  original's anchors.
- **Validator** (additive only): warns on G10/G53/G92 coordinate shifts, unknown G/M codes, M6 or
  M30 with the spindle running, M3 without S, motion before G90 and after M30.
- **GCodeReader** no longer traps on a huge T word or loops for ever on a tiny G83 Q.

### Crashes on hostile input
- Clipper2 threw C++ exceptions (inf or over-range coordinates) through the C boundary and
  aborted the app; the wrapper now catches them and `GeomKernel` drops unrepresentable paths.
- `Int(Double)` traps on NaN/inf in `Flattening`, the SVG arc parser, STL/OBJ/DAE import and
  `nearlyMeetingEnds`; mesh importers reject non-finite vertices.
- DXF: a SPLINE with no more control points than its degree indexed past the knot vector; blank
  lines or text after `EOF` and CR-only files were rejected; `nan`/`inf` group values trapped.
- Expressions: unbounded recursion on pasted `((((…`; capped at 64 levels.
- A `.kerf` with `"layers": []` trapped on first use; it gets a layer on load.
- Moulding with a zero-diameter tool, texture with no strokes, a tiny peck depth (millions of
  moves) and an empty Boolean result (which deleted both inputs) are all handled.

### Correctness
- SVG with a `viewBox` and only a width or height imported at 1 px per unit (a 100 mm part became
  26 mm); the missing dimension now follows the viewBox aspect.
- PDF and EPS fill operators did not close the subpath, so filled polygons imported as open
  vectors that pockets and V-carves ignore.
- A zero-width offset of an open path returned a closed polygon.
- Inlay only checked the clearance alone against the thickness; it now checks start depth plus
  clearance, and the pocket depth.
- Relief3D warnings overwrote each other; templates kept `projectOntoModelID` and
  `additionalModelIDs` from the old design.
- File > Save as Template… ran the *toolpath* template saver (Swift picked the overload without a
  defaulted argument), so job templates could never be created.
- A post named by the project but not installed became "Avid Mach4 (inch)" with no message and
  the next export wrote that id back into the project. It is now an error in the export sheets
  and the stored id is only changed when the user picks another post.
- An unreadable `tools.json` was overwritten by the seeded defaults on the next edit; it is
  copied aside first and the message says so.
- Deleting a layer moved its shapes to layer 0 regardless of sheet, side or keep-out role (clamp
  outlines became parts, bottom-side shapes jumped to the top); shapes stay on their sheet and
  side and clamp outlines go with their layer.
- Parametric sizes (`ShapeOrigin`) were stale after a uniform resize or unit switch; they follow
  similarity transforms now.
- Template placeholders were substituted in dictionary order (a tool named "Bit {S}" rendered
  differently between runs); one pass now.
- The tracing-image cache hashed the whole PNG on every redraw.
- 3D finishing fed steep descents at the cutting feed; above 45 degrees it uses the plunge rate.

### Tests
- Golden fixtures regenerated themselves when missing and then compared the output to itself;
  they never regenerate without `KERF_UPDATE_GOLDEN=1`. `zModesAgree` now checks every Z word
  differs by exactly the thickness (it compared line counts).
- Fourteen render smoke tests asserted `data.count > 1000`, which a blank PNG passes; they now
  assert distinct sampled colours (`AppTestSupport.looksDrawn`). Metal tests report as skipped
  without a GPU instead of passing silently.
- Deleted (tautological, helper-only, copy pins or dead code): `stubOperationsReportNotImplemented`,
  `collapsedSectionsStartClosedAndOthersOpen`, `scannerFindsTheMenuShortcuts`,
  `theScannerSeesLiteralsAndIgnoresIdentifiers`, `ops2DMouldingStraightRailStillUsesExact1D`,
  `passDepthsAreEvenAndBounded` (duplicate), `plainJoinStillReturnsJustThePaths`,
  `duplicateOffsetsCopies`, `theFullScreenGlyphIsNotUsedForZoomToFit`, `quickStartCoversTheWorkflow`,
  `bundleScriptCopiesSamples`, `quickStartSendsPeopleToJobSetupForTheMachine`.
- Rewritten to assert behaviour: `calculatingNeverCrashes`, `exportProducesTextOrReadableError`,
  `mirrorKeepsBounds`, `invalidJSONIsAReadableError`, `guidesSurviveCodingAndOldFilesDecode`,
  `notesOpenAutomaticallyOnlyWhenAsked` (polls instead of a fixed 50 ms sleep).

## Not fixed: ranked backlog

Each item names the file; the reviewer reports under `.tmp/deep-review.D4MzLK/` (not committed)
have the full scenario and evidence.

### Safety and correctness
1. **Relief roughing rapids into cusps** between raster levels when the region boundary is not
   profiled (`ReliefRoughing.swift:42`): keep raster lines at fixed offsets across levels or plunge
   from the top gap. Medium confidence, thin slivers.
2. **`snapshot()` marks the project saved before the file is written** (`KerfDocument.swift:190`):
   a failed save deletes the recovery copy. Promote `lastSavedProject` only after the write.
3. **Manual tab anchors attach to the nearest loop with no distance limit** (`TabAnchors.swift:47`).
4. **Tabs silently reduced to 0 or 1 on small parts** (`PassShaping.swift:105`): add a warning.
5. **Hole milling**: helix angle unbounded for holes barely larger than the tool; free-standing
   slug on through holes and thread mode's assumed pilot hole get no warning
   (`HoleMillOperation.swift:64-98`).
6. **No cut-depth check against `Tool.fluteLength`** anywhere.
7. **3D stepover floors of 1e-4** let a stepover-0 tool run 240 000 raster lines
   (`Relief3DOperation.swift:98`, `ReliefRoughing.swift:17`); rest machining is O(cells x radius^2)
   (`ReliefRest.swift:45`).
8. **Relief finishing links cross islands narrower than 2.5 x stepover** (`ReliefFinishing.swift:84`).
9. **Spiral/zig-zag ramps ignore `maxAngle` on short loops** (`PassShaping.swift:47-82`).
10. **Writer "repairs" an XY rapid in the material into a G0 plunge** (`GCodeWriter.rapid`); the
    toolpath validator already errors on the original move, so this is defence in depth.
11. **Keep-out check skips the first move** of the program (`KeepOut.swift:41`); two keep-out
    routines with different margins (`LayoutChecks.keepOut` vs `KeepOut.violations`).
12. **`ProgramBuilder` never emits `profile.spindleOff` (dead field) nor forces G90/G17**; a user
    post without them is only caught by the new validator warnings.
13. **DXF import ignores layer off/frozen and paper-space entities** (`DXFReader.swift:83`,
    `DXFImporter.swift:63`); Kerf's own hidden-layer export re-imports visible.
14. **CSV tool import defaults unknown units to inches** (`ToolLibraryExchange.swift:115`).
15. **Save All / Tiled write partial file sets on "Save Anyway"** and overwrite existing files
    without asking (`GCodeBatchExport.write`, `TilingSheet.save`).
16. **Unit switch leaves document variables unscaled and drops links** (`UnitScaling.swift:215`).
17. **`1in/2in` evaluates to 25.4 in a mm document** (suffix applies to the quotient).
18. **Vector export re-origins designs with negative bounds** on round trip (`SVGExporter.swift:18`).

### Robustness and performance
- Reference expansion (`<use>`, DXF INSERT, DAE instance) is depth-limited only: a self-referencing
  group expands 2^16 times. Add a shape budget per import.
- `joinOpenPaths` is O(n^2) on every DXF import (`PathOps.swift:78`); use the grid
  `nearlyMeetingEnds` already has.
- Gadgets: no memory bound, time limit fails open if `JSContextGroupSetExecutionTimeLimit` is
  missing, all on the main thread (`GadgetHost.swift:35-73`).
- No size limits on image or mesh import; every save and recovery tick re-encodes them on the
  main thread (`ImportService.swift:111`, `RecoveryStore.swift:124`).
- Array/copy counts capped per axis only (500 x 500 copies); texture spacing, nesting rotation
  step and fixture grids are unbounded.
- `cursorPosition` is `@Published` on the document, so every mouse move re-evaluates the whole
  window and re-flattens vectors in split mode (`KerfDocument.swift:138`).
- PDF import ignores `/Rotate` and `/UserUnit`, leaks one content stream per import, and can
  overflow `w * h * comps` on a hostile size.
- Voronoi wrapper: `int` narrowing above ~214 748 units, unbounded sample count for a tiny step.
- `KerfFile.formatVersion` is still 1 with an empty migration table; an older build drops newer
  optional keys on save.

### Missing against README / PARITY
- `tp-arc-output`: no generator emits helical arcs; only the post passes them through.
- Open vectors get no tabs, leads or overcut; 3D finishing has no Z-level or constant-scallop.
- No `G54` work-offset statement, no spindle spin-down dwell, no side name in two-sided headers

- SVG import silently mishandles `clipPath`, CSS classes, `switch`, `textPath` and nested
  viewports; DXF `$INSUNITS` beyond the common codes, MINSERT arrays, periodic splines.

### Test suite structure
- Tests write to the real user account: `PreferencesTests`, `PreviewTimeEstimateTests` and
  `IOClipartTests` leave `kerf-tests-*.plist` files in `~/Library/Preferences`;
  `AppTestSupport.tempDir()` never cleans up (thousands of leftovers in the user temp dir);
  `SimulationPreviewModel` writes `UserDefaults.standard`; `MachineConfigTests` and two layout
  tests read `~/Library/Application Support/Kerf`.
- Eleven test files need an installed Helvetica; two depend on SF Symbol availability.
- Three copies of the safety-invariant checker in test support, none checking material bottom.
- No test iterates every `OperationKind` in both Z-zero modes, or round-trips every kind's
  parameters through unit scaling and JSON. A table-driven matrix test would catch the next
  "tab computed from thickness" bug before it reaches the machine.
- `scripts/test.sh` has no minimum-count floor and there is no CI.
- Sample and golden generation lives inside the test target (`SampleFilesTests`, `EndToEndSignTests`).
